# Muse UI 管線化重設計

**日期：** 2026-07-25  
**狀態：** 已確認（brainstorm）  
**範圍：** `lib/web_app/` 前端殼層與工作流；`services.py` / `server.py` 中與 capture 落地、分流、庫掃描、任務相關的後端調整  

## 1. 問題

現有 Muse UI（`03_open_muse.bat` → `http://127.0.0.1:8765/`）視覺偏「行銷站」：大 Hero、襯線標語、抽象四步（探索 / 預覽 / 佇列 / 收藏），與專案真實 01→02 管線脫節。

真實管線（BAT / 目錄）為：

```text
搜尋或貼網址
  → 01 產生九宮格（output/01_preview_images/）
  → 人工把九宮格 JPG 移到
       output/02_preview_videos/  → LOW：最低畫質 30 秒 + 硬字幕
       output/03_videos/          → 正式：≤1080P + 外掛 SRT
  → 02 下載與字幕（run_download）
  → 播放 / 正式九宮格歸檔 04_downloaded/
```

現 UI 的落差：

| 現象 | 影響 |
|------|------|
| 「預覽」同時指瀏覽器短名單、九宮格、LOW 成片 | 語意衝突，無法貫穿 01/02 |
| 佇列按鈕直接「建 30s / 準備完整」 | 跳過「先審九宮格再分流」 |
| capture 後端把九宮格直接丟進 02 或 03 | 沒有 01／待分流審片關卡 |
| 收藏混 LOW + 正式 | 看不出目錄與狀態 |
| 過度美化、操作密度低 | 工具感弱，主路徑被裝飾淹沒 |

## 2. 目標與非目標

### 目標

1. UI 主軸對齊 01→02：搜尋 → 九宮格（審片 + 紀錄）→ LOW 或正式 → 下載字幕 → 播放。
2. 去美化：緊湊工具台，功能與管線狀態優先。
3. 任意時刻可見：待分流數、執行中任務、02/03 完成／字幕狀態。
4. 九宮格同時是**必經審片關卡**與**可回查紀錄檔**（略過仍保留）。

### 非目標（v1 不做）

- 瀏覽器短名單／「預覽分頁」復活
- Kanban 拖放看板
- LOW「升正式」完整自動串接（可留 v1.1 或灰階入口）
- BAT 維護模式完整 GUI（`--retry-subtitles` / `--repair-over-1080` 可先文案 + 開 log）
- 大範圍 i18n／主題系統重做（保留最小設定即可）

## 3. 已確認決策

| 決策 | 選擇 |
|------|------|
| 版面 | 階段分頁（Approach A） |
| 能力組合 | 管線主軸 + 本機庫/任務 + 頂部階段現況（原 A+C+D） |
| 短名單 | 移除；搜尋多選直接建九宮格 |
| 九宮格 | 必經；審片依據以九宮格圖為主 |
| 搜尋主動作 | 僅「建九宮格」，不直送 LOW/正式 |
| 下載啟動 | 使用者明確觸發（對應 02），不在分流時偷偷跑 |

## 4. 資訊架構

### 4.1 一級分頁（五個）

| 分頁 | 對應產物 | 職責 |
|------|----------|------|
| **搜尋** | 記憶體中的搜尋結果 | 跨站搜尋、多選、**建九宮格** |
| **九宮格** | `01_preview_images/` + 待分流索引 | 審片、紀錄查詢、分流 LOW/正式/略過 |
| **LOW** | `02_preview_videos/` | 待下載／處理中／完成／失敗；播放；啟動下載 |
| **正式** | `03_videos/` | 待下載／影片就緒／字幕中／字幕完成／失敗；播放+軟字幕；啟動下載 |
| **任務** | capture / download jobs | 進度、log、失敗提示、啟動/查看 download |

頂欄：精簡標題、本機提示、執行中任務角標（跳任務分頁）、設定入口。  
**刪除：** Hero、行銷 workflow 四步、與分頁重複的第二層 view-tabs、瀏覽器短名單狀態。

### 4.2 主流程

```text
搜尋 API 結果（session / 記憶體，不進 output 目錄）
  → 使用者多選 → 建九宮格
  → capture 落地到 01 或 staging，寫入「待分流」紀錄
  → 九宮格分頁審圖
       → 送 LOW   ：九宮格進入 02_preview_videos/（待下載）
       → 送正式   ：九宮格進入 03_videos/（待下載）
       → 略過     ：不進 02/03；紀錄狀態 = skipped，檔案預設保留於 01 側
  → 使用者按「開始下載與字幕」→ run_download.py
  → 掃描 02/03 更新庫狀態與可播放 URL
  → 任務列表輪詢 progress / log
```

## 5. 各分頁行為

### 5.1 搜尋

- 保留：關鍵字／URL、來源多選、頁數、結果網格、排序／篩選（可精簡 UI，邏輯可沿用）。
- 多選後 bulk bar **唯一主動作**：「建九宮格 (n)」。
- 卡片次要動作：開來源、必要時輔助解析播放（**不得**取代九宮格成為主審片路徑）。
- 不再提供「加入預覽／加入佇列」短名單。

### 5.2 九宮格（核心）

**角色：** 必經審片 + 紀錄檔。

**篩選：**

- 待分流（預設主佇列）
- 已送 LOW
- 已送正式
- 已略過
- 全部紀錄

**審片 UI：**

- 預設：左側／主區九宮格大圖（可放大）+ 右側決定面板。
- 可切「網格模式」多選，底部批次：送 LOW / 送正式 / 略過。

**單張／批次決定：**

| 動作 | 語意 |
|------|------|
| 送 LOW | 將對應九宮格置於 `02_preview_videos/`，狀態待下載 |
| 送正式 | 置於 `03_videos/`，狀態待下載 |
| 不要／略過 | 不進 02/03；保留紀錄與 01 側檔案供回查 |

**每筆紀錄至少包含：** 標題、來源站、原 URL、建立時間、batch／任務 id、狀態、關聯成片是否已存在。

**掃描：** UI 任務新建的九宮格與既有 `01_preview_images/` 批次目錄皆應可被列出（v1 以可掃描 + 狀態索引為準；舊資料無 URL 時狀態欄位可為 unknown／僅檔名）。

### 5.3 LOW（02）

- 狀態篩選：全部 / 待下載（僅有九宮格）/ 處理中 / 已完成 mp4 / 失敗。
- 已完成可播放；註明硬字幕。
- 「開始下載與字幕」與任務／正式共用同一 download 管線。
- **升正式：** v1 可不實作完整串接；若放入口須標示未完成或列入 v1.1，避免假裝可用。

### 5.4 正式（03）

- 狀態篩選：全部 / 待下載 / 影片就緒・字幕處理中 / 字幕完成 / 失敗。
- 對齊現有管線：正式片可先出現再補字幕；UI 必須分開「影片就緒」與「字幕就緒」。
- 播放本機 mp4 + 軟字幕軌道（有 srt／vtt 時）。
- 可提供「開資料夾」類輔助（若實作成本低）。

### 5.5 任務

- 列表：kind（capture / download）、state、progress、message、最近 log、時間。
- 同一時間僅一個 download 在 queued/running（沿用現有限制）；衝突時明確錯誤提示。
- 頂欄角標顯示執行中數量。
- 失敗項：顯示 message + 可展開 log；重試優先接既有能力，否則指引 log／BAT。

## 6. 後端變更要點

### 6.1 Capture 落地語意（必要）

**現狀：** `TaskManager.start_capture(quality=preview|full)` 建九宮格後直接 `move` 到 `PREVIEW_VIDEOS_DIR` 或 `VIDEOS_DIR`。

**目標：**

1. 建九宮格任務只負責產生 JPG 與「待分流」紀錄（落地 `01_preview_images/` 或專用 staging，但對使用者呈現為九宮格／01 階段）。
2. 新增分流 API（名稱實作時決定）：將指定項目標為 LOW / 正式 / skipped，並在 LOW／正式時把九宮格放到對應目錄（與現有 `run_download` 掃描 JPG 的契約相容）。
3. 下載仍呼叫現有 `run_download.py`；不在分流 API 內自動開 download。

### 6.2 狀態索引（必要）

僅靠檔案是否在某目錄**不足以**表達「略過」與完整歷史。v1 需要輕量持久化（例如 JSON 於 `tasks/` 或 `output/` 下專案慣用位置），至少：

- id、url、title、site、grid 路徑、status（`pending` / `low` / `full` / `skipped`）、timestamps、source task id

舊檔無索引時：掃描檔案系統推斷（在 02/03 的 JPG → 已分流；僅在 01 → 待分流或 unknown）。

### 6.3 庫掃描

- LOW 與正式分開 API 或同一 API 帶 `kind` + 更細狀態。
- 正式項回傳：`hasVideo`、`hasSubtitle`、播放 URL、字幕 URL。
- 待下載：目標目錄有對應九宮格、尚無完成 mp4（細節以 `run_download` 實際命名規則對齊）。

### 6.4 API 表面（規劃用，實作可微調路徑）

| 能力 | 變更 |
|------|------|
| 搜尋 | 可沿用 |
| 建九宮格 | body 改為「僅 grid」；不再用 preview/full 直接進 02/03 |
| 分流 | **新增** |
| 開始下載 | 沿用；錯誤訊息對使用者可讀 |
| 任務列表 | 沿用並確保前端任務分頁完整展示 |
| 庫列表 | 拆 LOW/正式狀態欄位 |
| 九宮格列表 | **新增**（含篩選 status） |

## 7. 視覺與文案原則（去美化）

- 刪除：大 Hero、襯線大標、背景光暈、花式 brand mark、裝飾性空狀態插畫優先級。
- 頂欄 + 五階段分頁 + 緊湊工具列；內容區高密度。
- 卡片：細邊框、小圓角、少陰影；狀態用文字／小徽章，不用大行銷色塊。
- 文案用管線詞：九宮格、LOW、正式、待分流、下載與字幕、任務。禁用「靈感／收藏／只要四步」類表述作為主 IA。
- 日夜主題與縮圖模糊／隱私可保留在設定，不佔主工作流。

## 8. 成功標準

1. 使用者只靠 UI 完成：搜尋 → 建九宮格 → 審圖分流 → 下載 → 在 LOW 或正式播放。
2. 分頁標籤或頂欄可持續看到：待分流數量、執行中任務數。
3. 略過項目可在九宮格「已略過／全部紀錄」找回。
4. 介面不再出現與管線衝突的「預覽分頁」短名單。
5. capture 完成後項目出現在九宮格待分流，而**不是**直接出現在 02/03 待下載（除非使用者已分流）。

## 9. 測試要點（規劃）

- 單元／整合：分流狀態機（pending → low/full/skipped）；略過不進 02/03。
- capture 任務完成後九宮格列表可見；目錄落點符合 01／staging 契約。
- download 互斥：第二個 download 請求被拒且訊息清楚。
- 庫掃描：僅 JPG、僅 mp4、mp4+srt 三種狀態標示正確。
- 前端手測：五分頁切換、批次分流、任務 log 展示。

## 10. 實作順序建議

1. 後端：待分流落地 + 狀態索引 + 九宮格列表／分流 API。  
2. 前端殼層：五分頁 IA、去 Hero／短名單／舊 workflow。  
3. 搜尋分頁接「建九宮格」。  
4. 九宮格審片 UI。  
5. LOW／正式庫與狀態。  
6. 任務分頁與頂欄角標。  
7. 回歸：對照 README 01/02 心智與現有 `run_download` 行為。

## 11. 風險

| 風險 | 緩解 |
|------|------|
| 舊 01 批次無 URL 中繼 | 掃描降級顯示；新流程強制寫索引 |
| 與磁碟手動搬檔並行 | 以目錄為準重新掃描；索引可重建 |
| 改 capture 破壞現有 UI 佇列 | 一次切換前端，不保留舊「直送 02/03」按鈕 |
| 狀態 JSON 損壞 | 掃描目錄重建 pending/low/full；skipped 可能遺失（可接受並在 UI 說明） |
